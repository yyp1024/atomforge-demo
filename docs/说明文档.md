# AtomForge · Atoms 笔试 Demo 说明文档



---

## 一、实现思路

### 1. 产品形态

复刻 Atoms 类平台的核心体验闭环：

> 用户用自然语言描述想要的应用 → Agent 流水线解析需求、规划结构、生成代码 → 沙箱实时渲染出可交互应用 → 用户继续对话迭代，或直接改代码 → 分享 / 导出 / 持久化。

为此设计了两个视图：

- **Home（首页）**：Hero 输入框 + 8 个模板卡片 + 数据统计 + 最近项目，降低上手成本；
- **Workbench（工作台）**：左侧 Agent 对话与流水线轨迹、右侧沙箱预览、可切换的代码面板，还原「AI 编程工作台」的体感。

### 2. Agent 引擎：规则引擎 + LLM 预留

演示版追求**确定性与可复现**（每次点都能得到稳定结果），因此核心生成链路采用**规则引擎**：

- `ENG.parse()`：意图解析（关键词 + 模板匹配，支持「做一个 XX，YY 主题」句式）；
- `ENG.plan()`：6 步流水线（需求解析 → 结构规划 → 代码生成 → 沙箱编译 → 联调检查 → 发布就绪）；
- `ENG.synthesize()`：按模板构建器生成 `index.html / style.css / app.js` 三个文件并组装成 `srcdoc` 文档；
- 迭代识别：对话中的「换成红色」「改深色」「改名」「紧凑」等意图映射到配置变更，**保留原模板语义**（这是修复过的一个真实 bug：迭代时曾把番茄钟误换成了待办模板）。

同时预留 `ENG.LLM.enabled` 接入点：把 `synthesize` 换成真实 LLM 调用即可升级为通用生成，UI、存储、沙箱全部复用。

### 3. 沙箱与持久化

- **沙箱**：生成应用渲染进 `<iframe srcdoc>`，代码与宿主页完全隔离；生成应用内部自带 `af-` 前缀的 localStorage 存储（待办、番茄统计、打卡记录刷新不丢）。
- **持久化**：项目 / 设置 / 引导状态分别存 localStorage；`window.addEventListener("storage")` 实现多标签实时同步（修复过并发覆盖问题）。
- **分享**：项目参数（模板 + 标题 + 主题色 + 深浅）压缩为 base64url 放进 hash，新窗口 / 新设备粘贴链接即可导入重建。

## 二、关键取舍

| 取舍点 | 选择 | 理由 |
| --- | --- | --- |
| 技术栈 | 零依赖单文件 HTML（原生 JS） | 评审零门槛：双击即用、无构建链、无服务端依赖；对「可测试性」最稳 |
| 生成引擎 | 规则引擎优先，LLM 预留接口 | 演示场景下确定性 > 生成多样性；避免无 Key 时 Demo 不可用 |
| 数据方案 | localStorage + 分享链接 | 免注册登录、天然满足持久化要求；分享链接替代云端同步 |
| 代码形态 | 3 文件（html/css/js） | 还原真实项目结构，代码面板可按文件编辑、热更新 |
| 模板范围 | 8 个高频工具型模板 | 覆盖「工具类应用生成」的典型诉求，也构成规则引擎可解释的边界 |
| 视觉 | 深蓝石墨 + 青绿/紫罗兰双强调色，工程实验室风 | 与「AI 构建平台」题材匹配，避免模板化 SaaS 观感 |

**明确不做**（避免伪实现）：注册登录系统、云端多人协作、真实 LLM 生成（预留未接）、生成应用的服务器端存储。

## 四、扩展规划（若继续投入）

按「对评审价值的提升幅度 / 成本」排序：

| 优先级 | 扩展项 | 说明 |
| --- | --- | --- |
| P0 | 接入真实 LLM 生成 | 打开 `ENG.LLM.enabled`，把模板构建器替换为 LLM 输出代码的解析 + 落盘；保留规则引擎作 fallback |
| P0 | 分享携带代码正文 | 让「编辑后的应用」也能完整跨设备迁移 |
| P1 | 生成应用库与重编辑 | 生成的应用本身可再次作为输入（应用套娃：Agent 迭代 Agent 产物） |
| P1 | 云端项目同步 | 极简后端（如 KV 存储）+ 匿名项目 ID，替代纯本地分享 |
| P2 | 更多模板/生成器 | 图表看板、表单收集、API 演示等中长尾模板 |
| P2 | 运行日志与调试台 | 沙箱内 console 回传，支持「应用出错了告诉 Agent 修」的闭环 |
| P3 | 多轮多文件工程 | 生成 >3 文件的项目（数据模型、多视图），工作台升级为文件树 |

优先级逻辑：P0 打通「通用生成」与「代码可迁移」两个最接近真实产品能力的缺口；P1 强化产品闭环（应用套娃、云同步）；P2/P3 是广度与深度扩展。

## 五、如何验收

1. 打开在线链接（或双击 `index.html`）；
2. 输入「做一个番茄钟，橙色主题」→ 观察 6 步流水线与沙箱渲染；
3. 继续对话「换成红色主题」「布局更紧凑」→ 预览实时变化；
4. 打开「<> 代码」→ 改 `app.js` 里的时长 → 「应用修改」→ 预览热更新；
5. 刷新页面 → 项目、对话、预览均恢复；「分享」→ 新窗口粘贴链接 → 导入成功；
6. 「下载」生成 HTML 单文件，双击可独立运行；设置页可导出全部项目备份。

## 附：开发过程与工具链

- 全程 vibe coding：需求拆解 → 分批构建 → 浏览器全流程实测（真实点击/输入/下载/导入）→ 视觉自检（桌面+移动截图、lint）→ 修复闭环，共修复 5 个真实功能 bug（层级覆盖、移动端布局塌陷、迭代误换模板、代码编辑不同步、多标签并发覆盖）。

- 视觉自检：无 console error / 无横向溢出 / 无资源错误。
